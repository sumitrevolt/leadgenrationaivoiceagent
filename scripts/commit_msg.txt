feat(deploy): canonical deploy_vps.sh — make unversioned/skewed deploys impossible

Both production faults found in today's audit came out of the hand-typed deploy
runbook, not out of application code:

  1. APP_VERSION forgotten -> compose fell back to ${APP_VERSION:-latest} -> prod
     ran an image whose provenance nobody could establish (/health: "latest").
  2. Only `app worker scheduler` were recreated -> worker_heavy/worker_video sat
     on an older :latest for DAYS = live version skew across containers sharing
     one image tag.

ADR-097's startup guard catches (1) at RUNTIME. This catches both at DEPLOY time,
which is cheaper and earlier.

scripts/deploy_vps.sh is now the canonical deploy:
  - refuses to deploy with a provenance-less tag (''/latest/dev/1.0.0), so the
    compose :-latest fallback can never silently decide the tag,
  - deploys ALL 5 app-image services (app worker scheduler worker-heavy
    worker-video) so skew cannot be reintroduced by omission,
  - verifies /health.version == the sha it just deployed and exits non-zero if
    not — a deploy that did not take effect can no longer be reported as success,
  - verifies per-container APP_VERSION (explicit skew gate),
  - smoke-tests revenue/auth paths + reports queues/DLQ,
  - DRY_RUN=1 prints the plan and changes nothing.

Landmines encoded deliberately (do not "simplify" away): set -o pipefail (a piped
build otherwise masks a non-zero exit); build log to /tmp (verbose output over the
SSH tunnel kills the session); worker-heavy/worker-video are HYPHENATED compose
service names (a wrong name aborts the whole `up`); run detached so a dropped
tunnel cannot SIGHUP-kill the build.

Build failure restarts NOTHING (prod untouched).

CLAUDE.md/AGENTS.md section 3 now points at the script instead of hand-typed
docker commands.

No app code touched. Verified by using this script to deploy itself.
